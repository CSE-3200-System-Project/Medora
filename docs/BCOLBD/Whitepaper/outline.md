# Medora 2.0 whitepaper outline

## Paper story

- **Opening/problem:** Bangladesh combines high household health expenditure,
  medicine dependence, a new personal-data regime, and rapid adoption of
  general-purpose models. The missing object is enforceable authority over what
  a model may see and do.
- **Challenge:** Prompt instructions do not implement consent, restrict reachable
  actions, provide source traceability, or guarantee transactional correctness.
- **Method:** Medora 2.0 composes five named artifacts around a deny-by-default
  policy chokepoint and assigns each one exactly one evidence status: deployed,
  measured, specified, or planned.
- **Evidence:** Report the deployed v1 system, medicine corpus, privacy fixtures,
  reviewed navigation fixtures, grounded-summary fixtures, and booking
  contention benchmark, together with the archived release-verification receipt.
- **Scope boundary:** Present Shimana, Maya, and the learned PHI recogniser as
  planned work, Arohon as specified over partly deployed controls, Lokkhon as
  measured, and Akkhor as deployed.
- **Impact:** Reframe Medora as open compliance and conformance infrastructure
  that complements existing EMR, HIE, telemedicine, and e-pharmacy systems.

## Section and paragraph roles

1. **Abstract:** problem -> containment method -> measured evidence -> limits.
2. **Problem and vision:** Bangladesh context -> exact technical gap -> objectives.
3. **Use case and existing solutions:** stakeholder workflows -> evidence-cautious
   comparison -> deployment screenshots.
4. **Five-artifact framework:** one stable sentence defining each artifact and
   how they compose.
5. **Arohon specification:** motivation -> specified tier data structure ->
   execution order -> risk ceilings -> finalist traces -> deployed/specification gap.
6. **Architecture and infrastructure:** trust boundary -> consent pipeline ->
   learned-task/deterministic-authority split -> model/data/status inventory ->
   transactional and database hardening.
7. **Evaluation:** planned Shimana protocol -> measured Lokkhon baselines ->
   planned learned PHI build -> planned Maya admission gate -> limitations.
8. **Risk register:** hazard, shipped mitigation, residual risk, evidence status.
9. **Akkhor and distribution:** corpus -> deployed search layer -> Akkhor remains
   open -> physician subscription hypotheses -> deployment-aligned cost envelope.
10. **Roadmap, team, conclusion:** built/proposed boundary -> finalist deliverables
    -> roles -> thesis restatement.

## Reverse outline

Every section maps to one BCOLBD scoring category. Each paragraph opens with its
message; details either explain a mechanism, supply evidence, mark status, or state
a limit. No paragraph exists only to list application features. The four-status
vocabulary and Latin-first artifact names are stable across prose, tables, and figures.
