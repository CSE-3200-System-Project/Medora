## Additional Roboflow sources supplied by the authors

The public [MedicalImage Universe project](https://universe.roboflow.com/medicalimage-z4t5b/prescription-oeiss) is discoverable without signing in. As checked on 23 September 2026, its page identifies an **Instance Segmentation** dataset under a **CC BY 4.0** licence, with about 1.6k images, seven classes, eight listed versions (v2–v9), zero listed models, and no published project description. The visible classes are `Date`, `Frequency`, `Lines`, `Medication`, `Passport-as2v`, `Pilgrim`, and `Quantity`. The page supplies no collection provenance, annotation guide, participant/consent statement, ethics determination, or source-image rights evidence. ([Project page](https://universe.roboflow.com/medicalimage-z4t5b/prescription-oeiss))

The latest visible public export, [version 9 (`p_v2`)](https://universe.roboflow.com/medicalimage-z4t5b/prescription-oeiss/dataset/9), says it was generated 10 September 2025 and contains 4,614 exported images: 4,518 train, 96 validation, and **0 test**. It specifies auto-orientation, fit resize to 640×640 with white edges, three outputs per training example, and grayscale/saturation/exposure/noise augmentations. These counts describe that public export, not an independent performance result; because it has no test split, it cannot by itself provide a held-out evaluation for the paper. The project and version pages show instance segmentation as the task, but do not expose a labeling protocol or validate the annotations' clinical meaning.

The supplied [workspace/version URL](https://app.roboflow.com/sarwads-workspace/prescription-oeiss-f5hvb-v8dd2/1) resolves to a Roboflow sign-in page when accessed unauthenticated. I did not sign in. Its URL identifies workspace `sarwads-workspace`, project `prescription-oeiss-f5hvb-v8dd2`, version `1`, but I could not inspect its actual images, class schema, split counts, augmentation, publication status, license, or model. The public source project instead identifies workspace `medicalimage-z4t5b` and project `prescription-oeiss`; the pages expose no link proving that the author's workspace version is a fork/copy of that public project. Similar project names are not enough to establish lineage. Obtain an account-side export/metadata record and original fork/import history to confirm the relationship and pin exactly which version trained the detector.

The source Universe page displays CC BY 4.0; that licence permits redistribution/adaptation with attribution and change notices, while warning that other rights may still limit a use ([CC BY 4.0 deed](https://creativecommons.org/licenses/by/4.0/)). Roboflow's [Terms of Use](https://roboflow.com/terms) separately state that datasets/content obtained from Roboflow may not be re-hosted without prior express permission from the dataset/content author, and that contributors to public projects grant Roboflow and users broad public-content rights while representing they hold rights including privacy/publicity/copyright rights. Preserve the displayed source licence/attribution and confirm that it covers the precise version and intended redistribution; it does not establish consent or ethics clearance for identifiable prescription images. The private workspace/version page did not reveal its own licence or visibility terms, so those remain unknown.

The Open Data Commons explains that ODbL applies to database rights, not automatically to copyright in individual contents, which may carry separate rights. For CC BY 4.0, the license requires attribution and notes that other rights can still limit a planned use. Kaggle's own [dataset guidance](https://www.kaggle.com/docs/datasets) treats the listed licence as the publisher's dataset licence; its [Community Guidelines](https://www.kaggle.com/community-guidelines-2025-02-24) also prohibit misrepresenting or violating a source's licence/terms. These are why an uploader's licence label should not be treated as proof of upstream permission. ([ODbL text](https://opendatacommons.org/licenses/odbl/1-0/), [CC BY 4.0 deed](https://creativecommons.org/licenses/by/4.0/))

## Supplied fine-tuned ONNX model

The author-supplied file at `ai_service/models/Yolo26s/Yolo26s-prescription-5.onnx` has SHA-256 `476ed2eaacaa8452ddc96a3a18e38b5cb60237c8cf14b78473cf314cecfdf2a8`, identical to the separately supplied file. Static ONNX metadata declares Ultralytics YOLO26s, detection, input `images` shaped `[1,3,640,640]`, output `output0` shaped `[1,300,6]`, and classes in the order `Date`, `Frequency`, `Lines`, `Medication`, `Passport-as2v`, `Pilgrim`, `Quantity`. Its metadata declares AGPL-3.0. Ultralytics states that its trained models are AGPL-3.0 by default and identifies an enterprise licence for use outside that licence's open-source terms ([Ultralytics licence information](https://www.ultralytics.com/license)). This is a material release-compatibility question because the Medora source currently declares MIT; authors/institution must decide the distribution terms before including the model in the public capsule/archive. This audit is not legal advice.

The class list matches the public Universe project's visible schema, but the model metadata only gives a local `data.yaml` training path; it does not identify the dataset version, provenance, train/validation/test split, or held-out results. It therefore does not prove that the weights came from the author's supplied workspace version, from public Universe v9, or from images with a documented consent/rights chain. The model's original default app mapping used only four class names in a different order, so class 0 was interpreted as `Medication` and the actual class-3 `Medication` detections were not. The default mapping is now corrected and a focused regression test checks the seven indices. Before any detector result is reported, rerun it against a pinned held-out set with the corrected code and document the split and rights basis.

A local timing check ran 5 warm-up and 50 measured inferences using a synthetic 1024x768 image, ONNX Runtime 1.24.4, CPUExecutionProvider, and 2 intra-op/1 inter-op threads on Windows 11 / AMD64. Model initialization was 121.86 ms; request-path latency was min 135.33, p50 138.73, p95 141.87, max 147.95, mean 138.49 ms. The synthetic input produced zero detections. These figures describe local detector latency only: they are not prescription accuracy, quality, or end-to-end deployed-app performance and are not manuscript evidence.

## What these pages establish for the SoftwareX evidence

- The pages establish that multiple medicine datasets exist and describe their declared contents and uploader-reported provenance. They do **not**, by themselves, establish that the consolidated 71,795-row reference is current, clinically correct, regulator-authoritative, free of source conflicts, or lawfully redistributable in the Code Ocean capsule. Resource 1 is explicitly a MedEx scrape; resource 6's older listing also pointed to that lineage but its current URL redirects; resource 3 is a Netmeds scrape and has no demonstrated Bangladesh-specific validation. A list of sources is not a row/field validation result.
- The user reports that a qualified doctor has already verified the sources. This audit cannot corroborate that private work from these public pages, and it does not assume it did not happen. It can be useful reviewer evidence if the authors preserve a dated record of the reviewer's qualification/role (with consent), sources and exact versions reviewed, fields and sample/coverage checked, method, discrepancies and adjudications, and the bounded conclusion. Clarify whether the doctor checked source credibility, a sample of rows, or the full set; those support different claims.
- DGDA is the appropriate official comparison source for a claim of registered-product alignment. Freeze a dated official register snapshot (or record query/export date and retrieval procedure where no export is offered), hash it, compare exact product identities and DAR values, manually adjudicate mismatches with the reviewer, and report denominators plus match/conflict rates. Do not infer alignment merely from a Kaggle description or DAR-looking column.
- For source/licence reproducibility, retain each exact dataset version, retrieval date, URL, file list, SHA-256 hashes, licence/terms snapshot, attribution, and permission correspondence. Resolve the MedEx, MedEasy and Netmeds source restrictions before including scraped datasets or their contents in a public capsule/archive. This is a rights-clearance item for the authors/institution, not a conclusion about applicable law.
- The public Roboflow Universe project provides a reproducible public dataset identity and preprocessing/split metadata for v9, but not image provenance, consent, ethics review, annotation protocol, or a test split. The supplied workspace/version remains account-gated and its relation to the public project is unverified. Record exact account-side project/version export metadata, lineage, source/licence and the model actually evaluated. For family/friend contributions, retain dated consent with scope (ML training, publication and redistribution), de-identification/ethics determination, annotation instructions, split identifiers, model/configuration, code and weight hashes, and held-out metrics. Public availability or a dataset licence alone does not demonstrate consent or ethical approval.
